# TCP_NODELAY 正式回归报告（2026-09-21）

## 正式改动

FileHub 现在会在 accept4() 成功后、将客户端连接加入 epoll 前设置 TCP_NODELAY。设置失败时关闭该连接，避免以未知 socket 状态继续服务。

此前的 A-B-A 和客户端 TCP_QUICKACK 对照记录见 [latency-investigation-20260921.md](latency-investigation-20260921.md)。

## 功能与检测器回归

- 严格编译参数 -Wall -Wextra -Werror -pedantic：通过。
- 原项目回归：36/36 通过。
- C 单元测试：通过。
- FileHub 集成测试：9/9 通过，覆盖慢客户端、分片请求、Range、断连、超时、配置重载、指标和并发退出。
- ASan/UBSan 下的 9 项集成测试：通过，无检测器报告。
- TSan 下的 9 项集成测试：通过，无数据竞争报告。
- Valgrind 3.27.1，并发 16 个下载、8 个提前断开：0 errors；退出时 0 bytes in 0 blocks；3 个继承的标准 FD。

## 120 秒混合稳定性回归

完整机器可读结果：[stability-tcp-nodelay-20260921.json](stability-tcp-nodelay-20260921.json)。

- 12 个并发客户端，共完成 309,503 次操作，错误为 0。
- 完整下载 103,444 次；分片请求 51,546 次；提前断连 51,518 次；Range 下载 51,439 次；状态查询 51,556 次。
- 每秒采样的 RSS 最小/最大值均为 2,424 KiB。
- FD 采样范围为 10–23，随活动连接数变化。
- 测试结束时保留慢接收连接并发送 SIGTERM；服务在 5.79 秒内以退出码 0 结束。
